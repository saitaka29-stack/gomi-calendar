# 要件定義書：ゴミ出しカレンダー

関連資料：[ユーザーストーリーマップ（T-04）](./user-story-map.md) ／ [情報設計（T-05）](./information-architecture.md)

## 1. プロジェクト概要

### 背景
- 引っ越すと地域ごとにゴミ出しのルール（曜日・分別）が変わり、なかなか覚えられない
- 自治体の分別表は紙や PDF で情報が多く、毎朝見るには向いていない
- 「第 2・第 4 金曜は不燃ゴミ」のようなルールは、今日が第何週かを数えないと分からず、出し忘れやすい

### 目的
- ルールを一度登録すれば、**アプリを開くだけで今日・明日に何を出すかが分かる**状態にする
- 「第何週」の数え間違いによる出し忘れをなくす

### スコープ
| 含むもの（今回：MVP） | 含まないもの |
|---|---|
| ゴミの種類（名前・色・曜日・第何週・メモ）の登録・削除 | ユーザー登録・ログイン、複数端末の同期 |
| よくある例（テンプレート）から始める | 自治体データの自動取り込み |
| 今日・明日のゴミの表示、2 週間の予定一覧 | 通知（プッシュ通知・メール） |
| ブラウザへの自動保存 | 祝日・年末年始の例外（v1.0 で検討） |

## 2. ユーザーストーリー

**ペルソナA：一人暮らしの社会人**
- As a 一人暮らしの社会人, I want アプリを開いたらすぐ今日と明日のゴミが表示されること, So that 朝の忙しいときに分別表を見なくて済む.
- As a 一人暮らしの社会人, I want 「第 2・第 4 金曜」のようなルールを登録できること, So that 第何週かを自分で数えずに済み、出し忘れがなくなる.
- As a 一人暮らしの社会人, I want よくある例から始められること, So that 最初の登録の手間が少ない.
- As a 一人暮らしの社会人, I want 2 週間先までの予定を見られること, So that 旅行や出張の前にいつ出せばいいか分かる.

**ペルソナB：同居している家族**（v1.0）
- As a 同居している家族, I want 共有リンクから同じ予定を見られること, So that 毎回聞かなくて済む.

## 3. 機能要件

| ID | 機能名 | 説明 | 優先度 | Phase |
|---|---|---|---|---|
| F-01 | 今日・明日の表示 | トップに今日と明日のゴミを、色と名前と出し方メモで大きく表示。ない日は「収集なし」 | 高 | MVP |
| F-02 | 2 週間の予定 | 今日から 14 日分の日付と、その日のゴミを一覧表示 | 高 | MVP |
| F-03 | ゴミの種類の追加 | 名前・色・曜日（複数可）・第何週（指定なし＝毎週、または第 1〜5 週を複数）・メモを登録 | 高 | MVP |
| F-04 | ゴミの種類の削除 | 一覧から削除（確認あり） | 高 | MVP |
| F-05 | よくある例から始める | 燃えるゴミ・資源ゴミ・不燃ゴミなどの例を一括で登録。登録済みがあれば上書き確認 | 中 | MVP |
| F-06 | 自動保存 | 変更のたびにブラウザ（localStorage）へ保存 | 高 | MVP |
| F-07 | ルールの説明表示 | 「毎週 月・木」「第 2・第 4 金」のように、登録内容を日本語で表示 | 中 | MVP |
| F-08 | ゴミの種類の編集 | 登録済みの種類を修正 | 中 | v1.0 |
| F-09 | 「出した」チェック | 今日のゴミに出したチェックを付ける | 低 | v1.0 |
| F-10 | 家族への共有リンク | 内容を URL に埋め込んで共有（読み取り専用） | 中 | v1.0 |
| F-11 | 休みの日の設定 | 年末年始など収集がない日を登録 | 中 | v1.0 |
| F-12 | 前の晩の通知・分別検索・自治体データ | 将来検討 | 低 | v2.0 |

### 判定ルール
- 「第 N 週」は **その月の N 回目のその曜日**（日付 1〜7 日＝第 1、8〜14 日＝第 2 …）。カレンダーの行ではない
- 第何週の指定がないものは毎週
- 日付は端末のタイムゾーン（日本時間）で判定する

## 4. 非機能要件
- **パフォーマンス**：初回表示 3 秒以内（モバイル回線）。外部 API を呼ばない
- **セキュリティ・プライバシー**：認証なし。データは端末のブラウザ内だけに保存し、サーバーに送らない。解析タグも入れない
- **可用性**：Vercel の静的ホスティングで配信
- **ユーザビリティ**：スマホ幅 375px で横スクロールが出ない。ダークモード対応。今日のゴミは操作 0 回で見える
- **品質**：判定ロジック（第何週・曜日）を単体テストで検証する

## 5. 制約条件
- **予算**：無料枠で完結（Vercel Hobby、GitHub 公開リポジトリ）
- **期間**：短時間で 1 周（課題 2 は 2 周目の習熟が目的）
- **技術**：React 19 + TypeScript + Vite + Vercel（課題 1 と同じ構成にして、手順の再現性を上げる）。DB は使わない
- **開発**：Claude Code で、CLAUDE.md のルールと Plan Mode（設計 → 承認 → 実装）で進める
